# RDDL model

| File | Purpose |
|---|---|
| `orchard_targets_mdp.rddl` | Domain used with the `full` (ladder-based) topology |
| `orchard_targets_line_mdp.rddl` | Domain used with the line-based topologies (`line`, M1, M2, M3), see below |
| `examples/instance_robot_a.rddl`, `examples/instance_robot_b.rddl` | Example instances as generated by `OnlineOrchardManager.write_instance()` |

Instances are generated by the manager in every decision cycle from the
current state (robot location, picked targets, workspace graph) and written
to PROST's benchmark directory next to the domain
(`~/prost/testbed/benchmarks/orchard_targets/`, see the setup steps in the
main README).

## Line-topology domain

The manager uses the domain `orchard_targets_line` when `~topology_mode` is
`line`. It is the same as `orchard_targets_mdp.rddl` without one
action-precondition clause, which PROST's reachability analysis otherwise
treats as a dead end on the sparse line topology. The removed clause is the
"forced action" constraint; the move/pick semantics stay the same, and an
idle step still costs -0.01.

The original file used in the experiments was lost, so this one was
rewritten from that description and has not been rerun against the
original results.
